# Dock Signal walking router (experimental, not production)

A bounded, browser-capable walk-ranking module for a Roosevelt Island / western Queens / east Midtown rectangle. The core computes a single shortest-path tree per origin, re-ranks fresh compatible Citi Bike stations with no network calls, and returns route distances, indicative minutes, and path geometry. It sends no current location or station choices anywhere. It is **not enabled in Dock Signal**.

## Evidence and current blocker

- Ingested 7.7 MB of public OpenStreetMap ways and their source nodes for 40.738, -73.979, 40.780, -73.929. Compiled 28,477 pedestrian graph nodes and 67,112 directed edges.
- Source metadata reports **June 1, 2026 (08:52:28 UTC)**. That exceeds the 30-day production gate and the other mirror timed out. Do not present results from this archived graph as current.
- On that archived graph, the Roosevelt Island landmark to the island subway entrance routed to 294 m (~4 min at 1.3 m/s). A point across the west channel returned no route instead of using the Queensboro Bridge overpass as an island entrance. An island-to-Queens cross-check also returns no certified route, even though the source has ways for the separately mapped Roosevelt Island Bridge sidewalk. Treat that as coverage failure, not a claim the bridge is impassable.
- Synthetic tests prove a shared pedestrian bridge connects otherwise separated banks, a foot-prohibited bridge does not, an elevated interior can't be snapped to, and stale operator reports are excluded even when the overall status response is fresh.

## Rebuild

Node 22+; no project dependencies. Use a fresh regional extract or make one low-volume request to a public Overpass instance subject to its usage limits. Never call the below from the app or pass end-user locations.

```sh
curl -fGsS --max-time 60 --data-urlencode data@scripts/overpass.ql \
  https://overpass.kumi.systems/api/interpreter -o /tmp/ri-extract.json
node scripts/build.mjs /tmp/ri-extract.json data/walk-graph.json
node --test
```

## Integration contract

1. Add a visible beta routing control. Load and validate the graph on first use with `prepareGraph`. Check `walkingGraphState` before showing walk estimates. Serve graph JSON separately under the license below; no API requests carry a user's location.
2. Pass the **whole station snapshot**, not a rendered list, into `withWalks(graph, origin, snapshot, {mode})`. It independently checks source and individual station freshness and does not route demo data. Callers must also respect an explicit operator fetch failure/stale state. Results are limited to supported connections, are sorted by walk distance, and use the current bike/dock mode.
3. If `null` or no eligible route is returned, leave the well-labeled straight-line mode available and show why walking routing is unavailable. Never use a straight-line distance to fill in a walking time. Keep the external walking-directions link for unverified areas.
4. Before production promotion, verify current graph date, origin-to-Queens route against the actually mapped Roosevelt Island Bridge sidewalk, endpoint connectivity on both sides, and representative fresh operator stations. Do not infer connections by lines crossing on a map or hand-author bridge geometry.

## Assumptions and omissions

Graph edges come only from adjacent OSM way nodes, not geometric line intersections. The conservative access profile honors explicit pedestrian restrictions, excludes motorways, vehicle bridge ways without foot permission, undocumented crossing shortcuts and indoor or conditional-access ways. It can miss lawful paths and does not guarantee wheelchair access, closure coverage, surface condition, ferry/tram service, signal delays, or safe walking conditions. Snap distance cap is 40 m to a ground-level connected OSM node; sparse networks, complex stations and rivers can make the conservative graph refuse a route. Walking time is distance divided by 1.3 m/s, rounded up.
